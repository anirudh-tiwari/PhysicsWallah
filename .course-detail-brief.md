# Course detail screen

## Objective and audience
Add a dedicated course-content screen to the existing PW Skills React app. Clicking an active course should open this screen; the selected course determines the screen's course label and lesson content. The user explicitly requested UI only based on `public/course-UI.jpeg`, with no backend integration.

## Reference and aesthetic direction
Use `/home/ashish/Documents/CodeAgent/travel/public/course-UI.jpeg` as the visual reference. Recreate its layout and visual language in the app, not as a copied screenshot:
- White, clean, mobile-first course page.
- Header with a back chevron, “Batch Demo Videos” title, and the existing coin/balance motif if practical.
- A full-width horizontal content tab row: Lectures (selected by default), Notes, DPP, DPP PDF. Selected text and underline use the purple/indigo from the reference; unselected text is gray.
- A vertically scrolling set of generous white lesson rows with subtle rounded corners/shadows; each row has a 16:9 thumbnail at the left, lesson title, duration and date, plus a vertical overflow affordance. Use a prominent play badge on thumbnail and a lock overlay like the reference.
- Match the reference’s typography scale, whitespace, and card density while remaining responsive on both mobile and desktop. Avoid introducing a different dashboard style.

## Dynamic content and UI-only scope
- Clicking an active card opens this screen and passes its selected course.
- Display the selected course name visibly under/alongside the “Batch Demo Videos” header.
- Populate placeholder demo lesson titles based on the selected course (at minimum, first lesson title incorporates the course name). Use the same lesson categories for all courses as demo UI data, clearly with no claim of real media playback.
- Tabs should switch between course-related placeholder rows for lectures, notes, DPP, and DPP PDF; no real media/download backend is requested.
- Back control returns to Batches, preserving existing app behavior.
- Do not create real video/media assets or use external image services. Make attractive thumbnail placeholders with existing local assets or lightweight CSS/native visual treatments and Lucide icons.
- Keep the Active / Explore tabs and all existing catalog interactions intact. The Explore course card behavior remains as it is unless changing shared code is necessary.

## Implementation and architecture constraints
- Existing app uses React 19 + TypeScript + Vite, custom local screen state in `src/App.tsx`, and global CSS in `src/index.css`.
- Add a real React page component at `src/pages/CourseDetail.tsx`; wire it into `App.tsx` via the existing screen-switching convention.
- Pass the selected course by name/string so private course types do not need to be exported from `Batches.tsx`.
- Add an active-course open callback prop to `Batches.tsx`. Keep opening from the active course card; do not make unrelated behavior changes.
- On the new screen use its own header and hide the normal batches header/bottom navigation, consistent with the course-page reference and existing `VirtualLibrary` screen treatment.
- Ensure semantic, accessible tab controls, selection state, keyboard access, responsive behavior, and accessible back button labels.

## Typography, colors, and assets
Use the existing system typography and Lucide icon package. Pick the screenshot's white/charcoal/gray/purple palette, matching the purple around `#6354c8`. No new dependencies or remote requests.
